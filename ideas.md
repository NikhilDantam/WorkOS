# WORKOS design brief

## Reference and design movement

The visual reference is Steep.app: calm editorial pacing, metric-led storytelling, disciplined whitespace, and product UI used as the visual proof. WorkOS is not a clone. It carries a distinct identity for outcome intelligence in skilling programmes: evidence-first, institutional, precise, and quietly confident.

## Core principles

1. **Outcome over placement.** Placement is one event in a longer livelihood journey.
2. **Evidence over assumptions.** Every major outcome carries source and confidence.
3. **Longitudinal by default.** The interface makes 30/90/180/365-day changes legible.
4. **Human in the loop.** Low-confidence records are visible and reviewable.
5. **Privacy by design.** Consent, role-based access, privacy-safe identifiers, and auditability are first-class.
6. **AI assists; it does not fabricate.** Outcome Intelligence explains recorded evidence and proposes interventions.

## Color philosophy

The base is a warm paper/stone canvas with charcoal and deep navy text. The primary WorkOS accent is a restrained cobalt-indigo used for links, selected states, focus rings and key analytical emphasis. Muted sage, amber and coral are semantic status colors only. Avoid neon, excess gradients, glow, noisy illustration and card-heavy decoration.

## Layout paradigm

Marketing pages use wide, editorial sections with an asymmetric grid: strong left-aligned statements, a visual proof panel, and deliberate vertical rhythm. Application pages use a compact left navigation rail, a utility top bar, and modular analytical surfaces separated by hairline rules rather than large rounded cards. Tables may be dense, but surrounding whitespace keeps the product calm.

## Signature elements

The signature mark is a three-node outcome path: a solid indigo node for the starting condition, a linked cobalt segment for evidence movement, and a dark charcoal terminal node for measured outcome. In the hero it becomes a connected journey graph. In the product shell it becomes the WORKOS mark and favicon. In empty states it appears as a small, confident path rather than a decorative illustration.

## Interaction philosophy

Interactions should feel consequential but calm: filters, drawers, tabs, charts, and timeline events update in place with 150–250ms transitions. Hover states reveal context; focus states are clearly visible. Demo mode turns the narrative into a guided measurement loop without hiding what is synthetic. Buttons use action-oriented language such as “Review verification”, “Create intervention”, and “Explore the platform”.

## Animation

Use understated opacity/translate transitions, chart line reveals, and path progression in the hero. Prefer CSS transitions and small keyed sequences. Avoid parallax, continuous motion, auto-advancing carousels, or animations that compete with data.

## Typography system

Use a clean sans-serif stack with a compact uppercase eyebrow style, large but not oversized marketing headings, readable 15–16px body copy, and a slightly denser application scale. Keep headings short, specific, and evidence-oriented. Use numeric tabular styling for KPIs and clear label/value contrast.

## Brand essence and voice

WORKOS should feel professional, calm, precise, trustworthy, data-driven, enterprise-grade, modern, and intelligent. Copy is direct and measured: “Employment conversion increased 8.4% across the selected cohort.” Avoid hype, fake certainty, empty AI claims, or informal dashboard language.

## Wordmark and project branding

Use `WORKOS` in a sturdy, slightly tracked wordmark beside the connected outcome-path mark. The favicon/project icon is an opaque full-bleed square PNG with a deep navy background and the path mark in solid cobalt/indigo/white shapes. The website favicon and header mark reuse the same identity. No text is baked into the icon.

## Planned visual assets

The primary visual assets are built from CSS/SVG product UI and charts so the application remains lightweight and owned by the product. No stock people photography is used. The only generated/uploaded project asset is the flat WorkOS icon required for project branding and favicon use.
